## Plain words, losses and recommendation

R should remember what the mascot should show now, rather than keep receipts for the last twenty calls. Each valid call changes that desired state as one unit. The browser receives the complete result with a version and mount number. If it has an older version, R sends the current result again. There is no delivery window to fill. Mood/status use the newest accepted values; a repeated mood still does not restart movement. Gestures remain separate one-shot actions.

Scenario: a results tab temporarily removes its mascot while an analysis sends 100 status updates. The last accepted state is alpha_visor, mood processing, bubble Scanning, status 100. When the tab returns with Tessa as its UI default, the server-owned alpha_visor and the whole current state arrive together. Nothing waits for twenty missing receipts, and processing is never validated against Tessa. If the server never owned the character, the new UI character wins and retained values follow the existing fallback rules.

What we lose or choose explicitly:

- Intermediate accepted status/mood pictures and older pending gestures need not be displayed. This is a latest-state protocol, not an event log; it does not promise every historical call becomes visible. Atomic validation still happens for each settled call.
- While removed, updates use the last known baseline unless the server owns the character. A call valid only for the next UI's character can be rejected. This removes dependence on the timing of the unmount notice.
- Before *any* baseline is known, the first valid explicit-character call establishes the startup target. Earlier unsettled calls are settled against that target in original order, then that explicit call is applied. This is an additional recommended startup rule, not a claim that the review already specified it. It can reject an earlier extra mood that would have been valid for a different future UI character. It avoids an unresolved prefix silently overwriting later accepted intent, without a second context journal.
- A dismissed bubble stays dismissed across remounts in the same connection. An open bubble is restored without restarting its timer. A later explicit bubble update, even with identical text, has a new bubble revision and can show again. This chooses the review's no-revival guarantee over today's reopen-on-remount behaviour.
- Duplicate simultaneous live ids are development errors. Full messages cost more than patches. Dynamic tokens are session-scoped; retention is bounded per id/reference, not globally across arbitrary app-created ids/templates.

**Recommendation:** approve this simpler state protocol, including the explicit startup and bubble rules, before U1. Keep whole-call atomicity, server ownership, lifecycle ordering, one-shot watermarks, static-UI support and real R/JS/app acceptance. Q1 remains blocked until founder approval and independent review of the replacement; runtime evidence remains U1/I1's job.

### 3.16 Motion scheduling and host behaviour

motion.change: style wiggle/hop/gesture (default wiggle), frames18, angle0.06, height8, swap_at0.5; gesture required for style gesture. motion.idle: frames150, blink_every120, blink_jitter30, blink_frames6, breathe0.012, breathe_period90, breathe_part root, extra null. Durations are finite and positive; blink_jitter+blink_frames/2 < blink_every. Breathe amplitude0..0.1, period>0. Change/idle frames integer1..150. Extra names one playable gesture and plays once; no loop.

Mount, a changed mood, gesture, changed held pose or play-after-pause begins one activity window of at most150 frames at30fps. A gesture replaces an in-progress change or gesture and commits the target mood immediately; a later mood change replaces the gesture and starts from the currently shown face. Repeating target mood does not restart. Same-call character/mood applies first; gesture follows. During an animated character swap a supplied valid gesture is discarded because the swap movement owns the window; reduced motion discards movement too. Independent idle/mood_change/gestures/swap/minimising/restoring/messages/others switches retain current meanings. A disabled gesture does not discard other valid fields.

All change, idle extra, effect and delayed tracks share the window's absolute deadline. Schedule a late effect/extra by proportionally fitting its finite duration into the remaining frames; if no frame remains, discard it. New distinct user/server actions can begin a new window, but queued effects/children cannot extend one themselves. Idle fades in the final third; crossing blink windows are skipped. At the deadline settle all channels/effects to the target rest, emit one final frame, cancel RAF. Pause freezes frame time; destroy cancels everything; hidden elements pause scheduling without replaying discarded actions when shown.

Enabling reduced motion settles immediately and clears pending movement. Disabling it does not replay old change/gesture/extra/swap/effects. Colour changes, resize/DPR changes, detail-band changes and redraw do not start activity. Held host gaze is instantaneous, not animation; it clears only look channels. No gaze channels are sent for faceless/no-gaze kits. Shiny status/ARIA use shown state, never a pending invisible target. Build the canvas accessible label from character display name plus shown status, never raw character/mood ids.

Character swap retains today's private-canvas fade, bounded out/in duration, captured outgoing state, retarget/reversal speed and no-visible-pending-target behaviour. Fit total phases to incoming activity budget. Mid-swap mood changes commit without wiggle and do not extend it. Reduction or swap:false finishes immediately; re-enabling never replays it. Same id/content is ordinary update; same id/different content is rejected before state change.

#### R-settled desired state and delivery

**Scope and atomicity.** This is a last-value-wins Shiny state protocol, not delivery of every historical call. Namespacing happens once. All update state, lifecycle state, counters, pending calls and ownership belong to one session and id. R validates an immutable prepared copy of each whole call against checked content before committing any of its fields. An invalid explicit preset/mood/gesture/click or other invalid supplied field rejects the bubble/status and every other field in that call with `mascot_update_ignored` inheriting `mascot_warning`, naming the id and reason. It changes no desired values, ownership, revisions or pending actions. Empty-helper resets own their field; NULL retains its existing public unchanged meaning.

The context is the server-owned character, otherwise the last known R-issued UI baseline. A valid explicit same-call character supplies its checked incoming context; apply the character/mood fallback and retained-theme/click adaptation rules atomically before committing. An invalid explicit-character call is rejected immediately, never an anchor. While unmounted, continue validating against this known context, even if an unseen future UI will use another character. This rule is independent of whether an unmounted notification arrives.

**Cold start with no known target.** Until any baseline or valid explicit character is known, retain whole calls in one unsettled context, with increasing original sequences. Structural errors reject immediately. For target-sensitive checks, use conservative canonical data-only guards; only checks proved universally valid may be omitted. Each guard bucket has F latest-field owner slots, but retains each owner's *complete original call*, including superseded fields within that call. Independent and proved guard-free calls share F slots. Drop a call only after it owns no slot in its bucket. Different guards cannot erase candidates: a valid earlier preset A must survive a later invalid preset B. Superseded unsettled calls have no acceptance outcome; accepted desired values are never removed this way.

Permit at most 20 distinct unresolved guards, plus the guard-free bucket: at most 20F + F retained original calls, with existing payload, depth and content limits still enforced. Reject an incoming overflow call as a whole, without changing the earlier buffer. Release empty buckets. One thousand same-context status calls keep only the newest status call; twenty guards can retain more than twenty calls.

The first ready supplies its validated UI baseline. Alternatively, the first explicit-character call that passes complete same-call validation establishes the startup character before any ready: use that checked character's default mood and normal helper defaults for previously unknown values. Settle the retained prefix against this initial context in sequence order, warning once for each retained invalid call, then atomically apply the explicit-character call at its original later sequence. Previously unknown UI values are not promoted into ownership. This startup-target choice is an explicit product rule; it is not validation against an unseen future UI. It eliminates a second unresolved context. Subsequent explicit characters and dependent calls settle immediately in R, so 100 alternating valid character updates cannot encounter a segment cap. A later real UI baseline uses the ownership table below.

**State held by R.** Keep the current accepted desired values and ownership mask for F fields, previous effective character/mood needed for fallback, the last known mount specification and generation/liveness, one increasing state revision, the latest accepted pending gesture with its action revision, a bubble revision, and acknowledged action/dismissal watermarks. Before context is known, additionally keep the bounded cold-start buffer above. Commit desired state on R acceptance, not browser acknowledgement. Maintain at most one replaceable latest outbound envelope per id/flush; do not retain a journal of older issued patches. An older acknowledgement cannot roll back R state. Counters are finite safe nonnegative integers, never silently wrapped.

**R to browser.** Send a private complete-state envelope `{generation, revision, state, gesture, bubble_revision}`. `state` is the complete effective state, with checked character identity/content reference and the applicable ownership/restore semantics. Include checked content on cache miss/first use; use a token alone only when its availability is established. A baseline change on a genuinely newer mount recomputes state and advances the state revision even without a new public call; it does not acquire ownership. Duplicate ready notices do not create a new revision. Restoring persistent state is not a new public action and does not restart an unchanged mood or replay old swap/change movement. The normal mount policy remains applicable.

Each complete state is prepared for one generation. The browser ignores envelopes for another generation and stale/equal revisions. For an applicable newer revision it prepares the whole state before installing it, so the character and its mood/theme/status cannot be validated against different targets. A complete-state invariant failure leaves the displayed state intact and reports a development error; it is an implementation disagreement, not a normal per-call rejection. R retains desired state and does not manufacture acceptance from that report. Correct the defect before U1 acceptance.

**Gestures and bubbles.** Keep the per-id browser ledger outside the DOM for the life of the connection. It holds the generation, applied state revision, highest consumed accepted gesture revision and bubble shown/dismissed state. A gesture is consumed at most once: record consumption before scheduling; policy-discarded and superseded accepted gestures count as consumed. Only the latest accepted pending gesture can play after final state establishes on startup/remount. Same-call character/mood establishes first; the unchanged motion/swap policy above may discard the gesture without discarding other fields. An old-generation envelope cannot consume a new generation's pending gesture. A lost acknowledgement is harmless while the connection's ledger survives; a repeated envelope cannot play an already consumed gesture.

Every explicit accepted bubble update, including identical text, gets a new bubble revision. Ordinary state updates/resends retain that revision. Dismissal is recorded in the ledger: the same bubble revision never reopens after dismissal, including after remount. An open retained bubble can be restored after remount using its retained visibility and remaining lifetime under the existing panel-timer policy; it does not restart on resend. Report dismissal/consumption to R, retaining the local ledger even if that report is lost. New connections start new session state; this is not an exactly-once promise across disconnects or crashes.

**Lifecycle and reconciliation.** The private browser snapshot is `{generation, mount_token, lifecycle, applied_revision, gesture_watermark, bubble_watermark, dismissed_bubble_revision}`. Use a connection-local monotonically increasing mount generation. Validate snapshot shape, safe counters, binding/token ownership and consistency with R-issued state before changing any server record. Unknown/foreign tokens, unsupported fields and impossible revisions/watermarks do not advance state. Mount and unmount, action/dismissal changes, state application and explicit reconciliation requests publish snapshots with event priority, even if values repeat; the binding's getValue returns its latest snapshot. No extra public Shiny input is introduced.

Unmount reports while the ledger is available, before controller/DOM teardown. It is best effort and terminal for that generation. A newer generation supersedes older lifecycle notices; an older ready cannot resurrect a dead generation. Old-generation reports cannot change current liveness or overwrite its baseline. Duplicate simultaneous live mounts of one id are development errors, detected in the browser before allowing a second authoritative binding; the first remains authoritative until its genuine unmount.

With no known live mount, R retains desired state and the latest pending action rather than sending to a dead element. A lost unmount can cause envelopes to target the absent old generation, but never loses R's accepted values or fills a delivery window. On a validated new ready, compute the ownership-table result and send the latest complete state for that generation, without waiting for outcomes from the old one. On a current live snapshot with a lower applied revision, resend the latest state; with an equal revision, do not resend. Coalesce duplicate recovery requests within a flush; never create an unbounded synchronous resend loop or new public revision just to retry. Lost/merged acknowledgements do not lose state; recovery occurs on a new ready or a delivered reconciliation snapshot. This assumes a functioning Shiny connection, not delivery while disconnected. No timeout resets accepted state or advances action watermarks.

**R-issued content and mount tokens.** Shiny binds only R-issued checked content and emitted UI specifications. A content token names checked character content; a distinct mount_token identifies the emitted UI specification, including its initial argument values and binding. Recognising character content alone never authorises another session's defaults. Static UI constructed outside a reactive domain has a lazily retained read-only process/template specification and can mount independently in two sessions; no session token must exist before constructing it. Dynamic UI and updates use session-owned descriptors/tokens, rejected in other sessions and released at disconnect. Tokens are identifiers, not credentials or catalogue-registration routes. No files, network or package-load side effects. The character catalogue remains separate from visitor status, bubbles and update state.

Retain descriptors only while referenced by static templates or by session UI specifications/current state/recoverable envelopes; page caches likewise release unused dynamic content. Do not keep a process-wide history of visitor-created characters. Token/cache reclamation must not strand a current envelope: attach content or request/resend the latest self-contained state on a cache miss. The resource claim is per retained id and bounded payload: O(F) settled state, plus at most 20F + F cold-start calls, ledger and referenced content. A session's total depends on its retained ids/specifications; static storage depends on app templates. Retain id state through remount until disconnect; no false fixed global bound. Same id/different checked content remains rejected under the existing identity contract.

**Remount precedence.** Observing UI defaults does not make them server-owned. Recompute persistent desired state before sending the complete restore. Adaptation of previously accepted values is restore, not rejection/re-evaluation of a new public call.

| Group | Remount winner | Revalidation |
|---|---|---|
| Character | Last accepted explicit server character override; otherwise newly rendered UI character. | A new UI token cannot erase a server-owned override. A newer accepted character call supersedes it. |
| Mood | Server-owned explicit mood, or effective mood derived from an accepted server character change; otherwise new UI mood. | Resolve against the winning character. Unavailable retained mood follows the previous effective character's fallback chain, then idle if unavailable. Never merge a stale outgoing explicit mood blindly. |
| Theme | Last accepted server theme/reset where owned; otherwise new UI theme. | Drop an unavailable retained preset with development `mascot_preset_dropped`, keeping valid explicit overrides over incoming native colours. An explicit new invalid preset rejects its whole call. |
| Independent fields (bubble/status/size/placement/motion) | Last accepted server value/reset where owned; otherwise each new UI value. | Recompute derived status from shown character/mood; literal status persists. No rejected mixed-call field survives. Bubble visibility/dismissal follows its separate ledger rule above. |
| Click | Last accepted server click/reset where owned; otherwise new UI click. | Clear an unavailable retained action group with a development diagnostic, keeping independent groups. A new invalid click call rejects its whole call. |
| Gesture | No consumed gesture is restored from persistent values. | Preserve consumed watermarks across mounts; only the latest still-unconsumed accepted action may play, subject to policy. |

The lifecycle/restore mechanism changes no public _click/_menu/_position/_minimised behaviour. Keep module namespace-once delivery, held host gaze, status/ARIA for shown state, theme reapplication, panel focus/timers, hidden layout, DPR/resize and teardown semantics. No output/render pair, htmlwidgets or runtime network. Browser-only/custom hosts may have their own validation stage; section 8's possibly-valid unknown browser target is not the Shiny route once this draft is adopted.
